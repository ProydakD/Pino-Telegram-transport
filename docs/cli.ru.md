# Руководство По CLI

Русская версия · [English version](cli.en.md)

Поставляемая утилита командной строки помогает заранее проверить доступ к Telegram и сгенерировать готовые фрагменты конфигурации для проектов на Pino.

## Установите Утилиту

- Установите пакет глобально: выполните `npm install -g pino-telegram-logger-transport`.
- Запустите одноразово через `npx pino-telegram-cli --help` внутри проекта.

## Проверьте Учетные Данные

- Запустите `pino-telegram-cli check --token <token>`, чтобы убедиться, что Telegram принимает токен.
- Добавьте `--chat-id <id>` (несколько значений разделяйте запятой), чтобы проверить доступ к каждому чату.
- Укажите `--thread-id <id>` вместе с единственным чатом, чтобы адресовать проверку конкретной теме форума.
- Добавьте `--probe-message`, если нужно проверить реальные права на отправку: CLI отправит беззвучное тестовое сообщение и сразу попытается его удалить.
- Без `--probe-message` команда `check` остаётся read-only: проверяет токен и доступность чатов через Bot API, но ничего не публикует.
- Чтобы все шаги, включая удаление пробного сообщения, шли через прокси, задайте `TELEGRAM_PROXY_URL` или передайте `--proxy-url`. Флаг важнее переменной окружения. Адрес с паролем лучше передавать через окружение, а не сохранять в истории команд.
- Опустите явные флаги, если переменные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `TELEGRAM_THREAD_ID` заданы в окружении.
- На каждый сетевой запрос CLI отводится 10 секунд, включая подключение к прокси и чтение ответа. Шаги одного запуска `check` могут переиспользовать туннель.
- При установлении TCP-соединения с прокси CLI может попробовать другой IP, но не повторяет запросы после отказа CONNECT или Bot API.
- Неверный [адрес прокси](configuration.ru.md#поведение-клиента) или неуспешная проверка дают ненулевой код. При отказе SOCKS5 в авторизации CLI предлагает проверить учётные данные прокси, не выводя их.

### Пример

```bash
pino-telegram-cli check --token 123:ABC --chat-id -1001234567890 --proxy-url socks5h://proxy.example:1080
```

```bash
pino-telegram-cli check --token 123:ABC --chat-id -1001234567890 --thread-id 777 --probe-message
```

## Сгенерируйте Конфигурацию

- Получите JSON-фрагмент командой `pino-telegram-cli generate-config --token <token> --chat-id <id>`.
- По умолчанию CLI подставляет в вывод плейсхолдер `<YOUR_BOT_TOKEN>`, даже если токен передан через флаг или окружение.
- Добавьте `--include-token`, только если нужно явно записать реальный токен в JSON или `.env`.
- Тот же флаг или переменная окружения добавляет `proxyUrl` в JSON либо `TELEGRAM_PROXY_URL` в env. Если в URL есть учётные данные, он целиком заменяется на `<YOUR_PROXY_URL>`, даже при `--include-token`.
- Выберите формат `.env` через `--format env`, чтобы дополнить файл окружения.
- Укажите `--output путь/к/файлу`, чтобы записать результат вместо вывода в консоль.
- Перечислите несколько получателей через запятую, чтобы в JSON появилась коллекция чатов.
- Заполните плейсхолдеры заранее, экспортировав `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` или `TELEGRAM_THREAD_ID`.

### Пример

```bash
pino-telegram-cli generate-config --token 123:ABC --chat-id -1001234567890 --format env --output .env.telegram
```

```bash
pino-telegram-cli generate-config --token 123:ABC --chat-id -1001234567890 --include-token
```

## Коды Возврата

- 0: все проверки прошли успешно или конфигурация сформирована.
- 1: некорректные аргументы, ошибка сети, прокси или проверки Telegram либо ошибка записи файла.
